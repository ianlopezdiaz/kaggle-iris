# Multiclass Classification on the Iris Dataset

This repository presents a case study in multiclass classification using the classic **Iris Flower** dataset.

The project is designed as a portfolio piece, demonstrating the typical stages of a supervised classification project - from exploratory data analysis to feature engineering, model comparison, and evaluation.

The accompanying Quarto website documents every step of the workflow and is available at:

**[https://ianlopezdiaz.github.io/kaggle-iris](https://ianlopezdiaz.github.io/kaggle-iris)**

---

## Project Overview

The objective is to predict the species of an Iris flower (setosa, versicolor, or virginica) from its sepal and petal measurements.

Rather than focusing exclusively on a single leaderboard metric, this project emphasizes good machine learning practices and a clear analytical narrative: which measurements separate the species well, and where the remaining classification error concentrates.

The complete pipeline includes:

* Exploratory Data Analysis (EDA)
* Feature engineering (derived measurements, dimensionality reduction)
* Feature scaling
* Model training across multiple classifiers
* Cross-validated model comparison and evaluation

---

## Dataset

The project uses the **Iris Flower Dataset** from Kaggle.

* Dataset: [https://www.kaggle.com/datasets/arshid/iris-flower-dataset](https://www.kaggle.com/datasets/arshid/iris-flower-dataset)

150 rows, 4 numeric features (sepal length/width, petal length/width, in cm), and 1 target (species), perfectly balanced across the three classes.

## Running the Project

### Install the dependencies

Create the Conda environment:

```bash
conda env create -f environment.yml
```

If desired, you may change the environment name inside `environment.yml` before creating it.

---

## Building the Documentation

This repository uses **Quarto** to generate the project website.

Preview the website locally:

```bash
quarto preview
```

Render the complete site locally (output goes to `_site/`, which is gitignored and not committed):

```bash
quarto render
```

Publish the site to GitHub Pages:

```bash
./scripts/publish.sh
```

This executes every notebook in `notebooks/` in place, then runs `quarto publish gh-pages --no-browser --no-prompt`, which renders the site and pushes it directly to the `gh-pages` branch.
